malformed log entries should probably not stay in the log

if we lose the last appplied index, we want to let the leader heartbeats automatically correct the state. We already have the apply worker that will apply logs to the state as the leader's commit index changes. So in case we lose our meta file on restart, there are different paths this could go down.
1. Election will happen and if a different node wins, heartbeats will automatically correct this. In the meantime, we cannot respond to requests safely so it will be in a non-linearizable mode. The node will ask clients to retry. During heartbeats, the last applied will still be 0. So when the current node sees the leader's commit index, it will then try to advance its state by appying entries from its log up to the leader's commit index. The follower node will ensure linearizable reads by checking if last_applied_idx has advanced and if it matches commit_idx (if it is not zero).
2. If during election the current node wins, it's a bit more tricky. The node has to find out what point in its log is committed and apply up to that point before it can start serving requests. After a single *successful* heartbeat round (i.e we get at least quorum responses back), we can apply up to just before the lowest conflict index we got back. If less than quorum nodes don't get back, we can't apply anything yet.
3. Add data length info to log lines for safe parsing
